# FluidCapsule 官方规则订阅设计

日期：2026-09-30

## 目标与已确认的选择

让常见验证码和验证链接措辞的后续调整可以通过 GitHub 规则包交付，而不必每次重新发布 APK。首版只订阅 FluidCapsule 官方 GitHub 仓库；订阅默认开启。用户进入流体胶囊时检查更新，只在应用内看到更新提示，点击“立即更新”后才下载并启用规则。规则页还提供手动检查入口。现有验证码、验证链接和普通链接的误捕边界必须保留。

这项功能与当前待提交的 OTP 漏捕修复、验证链接按钮一起进入下一版正式 APK。第一次 APK 更新负责安装订阅引擎；此后只有词组和受支持模板变化时，可以只发布规则包。需要新的解析算法、按钮或规则类型时，仍发布 APK。

## 范围与边界

规则包仅包含数据，不执行代码，也不接受任意正则表达式或外部订阅网址。首版支持以下固定类型：

- OTP 提示词：追加到现有关键词集合，用于现有候选码评分流程。
- OTP 绑定模板：由有限的模板类型、字面词组和验证码占位符组成，支持“提示词在码前”和“提示词在码后”，字面词组与码之间的最大距离由客户端限定。现有候选码长度、歧义判定、金额／日期／电话／订单／网址排除等防误捕逻辑继续生效。
- 验证请求词组：明确表达尚需验证的字面词组。客户端继续要求 HTTP(S) URL 与请求就近关联、只选唯一可确定的网址；没有可见网址时只能使用原通知已提供的打开入口。
- 排除词组：只能增加排除条件，不能关闭 APK 内置的排除规则。

远程规则与 APK 内置规则叠加，不能降低内置评分阈值、扩大可捕获的来源应用、改变隐私设置或替换打开链接的代码路径。若一种新通知格式无法由固定模板准确表达，需在下一版 APK 扩展规则引擎。

## GitHub 文件与信任边界

规则放在现有 `Venompool888/FluidCapsule` 仓库的 `rules/stable/`：

- `manifest.json`：规则版本整数、格式版本、最低兼容 APK `versionCode`、规则包的 SHA-256 摘要和简短更新说明；不含用户数据，也不含任意下载网址。
- `manifest.sig`：对 `manifest.json` 原始字节的 Ed25519 签名。
- `packs/<version>.json`：该版本的完整规则包，版本号与清单一致。

APK 内置官方签名公钥，只从固定的 GitHub HTTPS 主机和仓库路径读取这些文件。检查更新时先验证清单签名，再比较版本；点击更新后按清单中的版本构造固定包路径，下载规则包并核对 SHA-256。私钥保存在仓库外，发布脚本只读取本地私钥，不把私钥或凭据提交到 Git。公钥轮换需要 APK 更新。

规则包解析器采用严格字段白名单，拒绝未知字段或格式版本、重复规则 ID、无效模板参数，以及比已安装版本更旧的包。清单最多 8 KiB，规则包最多 64 KiB、200 条规则，单个字面词组最多 120 个字符；网络读取也按这些上限截断。客户端不会因远程数据而连接第三方 URL。签名、摘要或规则校验任何一步失败，都不替换当前规则。

## Android 数据流与本地状态

1. 启动时先加载 APK 内置规则，再读取应用私有目录中的最近一次已验证规则包；解析成功后组成不可变规则快照，供通知监听器读取。
2. 进入应用前台时，在后台线程检查官方清单；最近 6 小时已成功检查过则使用缓存，手动“检查更新”始终发起网络检查。检查不阻塞主界面，不在设备解锁时运行，也不注册周期性后台任务。
3. 发现高于当前版本且兼容此 APK 的规则时，在应用内每个新版本提示一次“立即更新／稍后”。规则页持续显示可用版本和手动更新按钮；“稍后”不自动安装。
4. 点击更新后下载、验证、解析完整包，再通过原子文件写入应用私有存储并一次性切换内存快照。正在解析的一条通知继续使用原快照，下一条开始使用新快照。
5. 本地保留当前和前一个已验证规则包，以及 APK 内置规则。规则页提供恢复内置规则入口；恢复后只有用户主动点击更新，或出现更高的官方规则版本，才再次提示安装。

规则页显示订阅开关（默认开启）、当前规则版本、最近检查结果、“检查更新”和“恢复内置规则”。关闭订阅会停止进入应用时的自动检查，不删除已安装规则；用户仍可手动检查。无网络、GitHub 错误、签名失败或不兼容时，界面显示简短状态，通知解析继续使用已验证规则，不反复弹窗。提示只出现在流体胶囊应用内，不发布系统通知或流体胶囊事件。

## 隐私与安全

新 APK 需要 Android `INTERNET` 权限，并更新 README 与隐私文档中“无联网权限”的现有描述。规则检查和下载仅发出固定 GitHub 资源的 GET 请求；请求中不包含通知正文、验证码、验证链接、历史记录、设备标识或已安装应用列表。通知内容仍在设备上解析，诊断日志只记录规则版本、检查结果和失败类别，不记录远程原文或私密通知内容。

规则包发布需要审阅和自动测试。规则文件本身可公开，但真实 Pixel 通知导出继续留在 Git 忽略的本地私有目录；仓库中的回归样例只使用脱敏合成文本。官方仓库或传输路径提供文件，内置公钥决定是否接受更新。

## 测试与发布验收

- 规则格式测试：各固定模板、版本兼容、大小及条目上限、重复 ID、损坏 JSON、未知字段／格式的处理。
- 完整性测试：有效签名能安装；篡改清单、替换规则包、降级、使用未知密钥或不兼容 APK 时拒绝并保留原规则。
- 解析回归：当前 OTP 和验证链接测试全通过；普通网址、指南、已完成验证、误导性标题、多个 URL 等不得被误识别。用本地私有 5,126 条历史正文只读重放，比较更新前后分类变化，不将内容写入仓库。
- 模拟器流程：自动检查、手动检查、稍后、点击更新、断网、恢复内置规则；发送脱敏合成通知，核对捕获结果和“打开验证链接”按钮。
- 完整 `testDebugUnitTest`、`lintDebug`、Debug／Release 构建通过；在 Pixel 11 Pro XL 上检查覆盖安装和应用内更新流程。正式签名 APK 沿用现有 keystore，保留用户设置及本地历史。完成验证后发布下一版 GitHub Release，并在说明中区分 APK 功能更新与后续规则包更新。

## 不包含在首版中的能力

第三方订阅源、规则包中的任意正则／脚本、后台周期检查、系统通知提醒、自动安装规则、静默修改白名单、跨设备同步，以及 APK 自更新。
